## 1. Фича (что делаем)
Вкладка **«Импорт»** в разделе «Товары» админки: скачать шаблон `.xlsx` → заполнить → загрузить → **предпросмотр** (что добавится/обновится + ошибки) → подтвердить → импорт. Плюс вкладка **лог импортов**. Отдельный **чистый** шаблон — НЕ legacy google-формат (google-sync не трогаем).

## 2. Залоченные решения (IMPORT-001 — не пересматривать)
- **Колонки шаблона:** Артикул\*, Наименование\*, Стоимость ₽\*, Остаток\*, Цвет, Размер, Описание, Бренд, Материал, Страна, Скидка %. (`*` обязательные.) Категории/подкатегории/фото/вес/габариты — **из админки, не из файла**.
- **Дубли SKU:** режим на выбор при импорте — `mode=new` (дубль → ошибка строки, существующий не трогаем) / `mode=upsert` (обновить существующий).
- **Ошибки:** частичный импорт — валидные пишутся, невалидные → в лог с `row#` + причиной.
- **Процесс:** предпросмотр (`dryRun`) → подтверждение → импорт. Preview = импорт с `dryRun=true`.
- **Лог:** персистентный (кто/когда/файл/режим/counts/ошибки).

## 3. Мои находки по коду (использовать как факты)
- Продукт-схема: `backend/src/schemas/crm-catalog.schemas.ts` (`createCrmCatalogProductSchema`) — принимает `sku,name,price,description,discountPercent,inStock,color,size,specs,weightGrams,dim*Cm,categoryId…`.
- Write-path (импорт ОБЯЗАН идти через него, не в обход): `crm-catalog.service.ts` `createCrmCatalogProduct`/`updateCrmCatalogProduct` (транзакции, денормализация).
- Multer xlsx-upload + паттерн `dryRun` уже есть: `crm-catalog-import.controller.ts`, `crm-catalog-import.service.ts` (это google-формат — переиспользовать multer/паттерн, но НЕ формат).
- Маппинг колонка→spec: `crm-catalog-sheet-map.ts`. Канон spec-ключей (как читает admin `ProductEditPage.tsx`): `Бренд`, `Материал`, `Страна производитель`; Цвет/Размер — dual-write (`color`+`specs['Цвет']`, `size`+`specs['Размер']`).
- Экспорт (основа генерации шаблона, там же xlsx-пакет проекта): `crm-catalog-export.service.ts`.
- Лог: `catalog-sync-history.service.ts` — reuse если схема подходит, иначе новая таблица.
- Последняя миграция = **040** → новая (если нужна) = **041**.
- `products.discount_percent NUMERIC(5,2)` (PRICE-001: `price`=LIST, sale вычисляется).
- **RU-числа обязательны:** в таблице заказчика цена `"3 500,00"`, остаток `"2,00"`, — парсер нормализует пробел/NBSP-разряды и `,`→`.`.

## 4. Декомпозиция (тебе — написать промпты)
**Фаза 1 — backend** (референс уже есть: `.tasks/2026-08-06-IMPORT-P1-backend.prompt.md` — можешь взять как основу или переписать):
- `GET /import/template` → .xlsx (11 колонок + пример + памятка).
- `POST /import/products?dryRun=1&mode=new|upsert` → preview `{summary,rows[{row,sku,action:create|update|error,errors[]}]}`, без записи.
- `POST /import/products?dryRun=0&mode=…` → commit: валидные через write-path, невалидные пропустить+вернуть, записать в лог, `+importId`.
- `GET /import/log` (+ `/:id`).
- Валидация построчная (частичная); нет обяз.колонки → 400 весь файл.
- Тесты vitest обязательны.

**Фаза 2 — admin-UI** (`muru-backend-local/admin/`):
- Вкладка «Импорт» в разделе «Товары»: кнопка скачать шаблон; загрузка файла; переключатель режима new/upsert; таблица предпросмотра (create/update/error + причины построчно); кнопка подтвердить → commit → результат; вкладка/секция «Лог импортов».
- Контракты берёшь из отчёта по Фазе 1.

## 5. Guardrails (жёстко)
- Не трогать: google-sync legacy импорт/формат; платежи/CDEK/auth/settings; storefront.
- Импорт только через существующий write-path (валидации/транзакции), без прямых INSERT в обход.
- Импортированные товары — без категории (категоризация/фото потом в админке).
- Prod/staging не трогать до отдельного STOP-гейта; verify (build+vitest) до PROGRESS.
